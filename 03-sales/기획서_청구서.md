# 월별 거래처 청구서 PDF 만들기 기획서

## 목표

`매출.xlsx`에서 지정한 연도와 월의 매출을 거래처별로 모아 `청구서.xlsx` 양식에 넣고, 거래처마다 PDF 파일 하나를 `PDF` 폴더에 저장합니다. 이번 작업에서는 기획서만 작성하며 프로그램과 PDF는 만들지 않습니다.

## 파일 구조

```text
03-sales/
├─ 기획서_청구서.md
├─ 매출.xlsx                 # 매출과 거래처 정보 원본
├─ 청구서.xlsx               # 청구서 양식 원본
├─ 청구서_만들기.py          # 추후 작성할 프로그램
└─ PDF/                      # 완성된 청구서 PDF
```

원본 엑셀 두 파일은 읽기만 하고 바꾸지 않습니다. PDF 폴더가 없으면 생성합니다.

## 확인한 엑셀 구조

- `매출.xlsx`의 `매출` 시트: 1행에 제목이 있으며, 필요한 열은 `매출일`(A), `상품명`(G), `거래처코드`(K), `거래처명`(L), `매출수량`(M), `단가`(P)입니다.
- `매출.xlsx`의 `거래처` 시트: `거래처코드`(A), `거래처명`(B), `우편번호`(C), `주소`(D)가 있습니다. 거래처코드로 매출과 주소 정보를 연결합니다. 우편번호 앞자리 0을 보존합니다.
- `청구서.xlsx`의 `청구서` 시트: 우편번호는 B5, 주소는 B6, 거래처명은 B7에 입력합니다. B5:G5, B6:G6, B7:G7은 각각 합쳐진 셀이므로 맨 왼쪽 B열에 입력합니다.
- 내역 입력란은 20~35행으로 기본 16행입니다. 날짜는 A열, 상품명은 B열, 수량은 F열, 단가는 G열에 넣습니다. H열에는 각 행의 금액 계산식이 있습니다.
- H36은 매출 합계, H37은 합계의 10%에 대해 소수점 아래를 버리는 부가세 계산식입니다. E17, G17, I17은 각각 매출액, 부가세, 이 둘을 더한 청구액을 표시합니다. 양식의 계산 기준을 유지합니다.
- `청구서 BackUp`과 `청구서(sample)` 시트는 원본에 있으며, 실제 청구서는 `청구서` 시트를 기준으로 만듭니다.
- 확인 당시 2026년 10월 매출은 11개 거래처에 있으며, 거래처별 내역은 최대 8행이었습니다. 매출일의 연도·월과 거래처코드를 묶어 행 수를 직접 세었습니다. 실제 실행 시에는 원본의 현재 내용을 다시 읽습니다.

## 처리 순서

1. 프로그램과 같은 폴더의 엑셀 파일을 엽니다. 연도와 월을 모두 생략하면 **2026년 10월**을 사용합니다. 연도와 월을 모두 입력한 경우 해당 월을 사용합니다. 하나만 입력하거나 유효하지 않은 값이면 사용법을 알리고 중단합니다.
2. 해당 월 1일 0시 이상부터 다음 달 1일 0시 미만까지의 매출을 선택합니다. 이 방법으로 월의 마지막 날과 윤년도 처리합니다.
3. 선택한 매출을 거래처코드별로 모으고, `거래처` 시트에서 해당 코드의 이름, 우편번호, 주소를 찾습니다. 매출이 없는 거래처는 청구서를 만들지 않습니다.
4. 필수 제목과 필요한 값, 날짜·수량·단가, 거래처코드의 누락이나 중복을 먼저 검사합니다. 거래처를 찾지 못하거나 필요한 자료가 올바르지 않으면 문제의 위치를 알리고 해당 실행을 중단합니다.
5. 각 거래처마다 청구서 양식의 작업용 사본을 만듭니다. 거래처 정보와 해당 월의 내역을 채우고 기존 계산식을 사용합니다. 내역은 매출일 순으로 정렬하며 같은 날짜는 원본 행 순서를 유지합니다.
6. 내역이 16행을 넘으면 양식의 내역 부분을 필요한 만큼 늘리고 서식·행별 금액식·합계 참조 범위가 모든 내역을 포함하도록 조정합니다. 한 거래처의 모든 내역과 전체 합계는 페이지가 늘어나더라도 하나의 PDF에 담습니다. 페이지가 나뉘어도 내용이 잘리지 않도록 확인합니다.
7. 엑셀 계산식을 다시 계산할 수 있는 프로그램에서 작업용 사본을 연 뒤 PDF로 저장합니다. 파이썬의 `openpyxl`은 계산식을 직접 계산하거나 PDF를 만들지 않으므로, 이 기능을 제공하는 Microsoft Excel 등 별도 프로그램이 필요합니다. 실제 작성 전에 사용할 프로그램과 설치 여부를 확인합니다.
8. 파일 이름은 `YYYY-MM_거래처코드_거래처명.pdf` 형식으로 만듭니다. 예: `2026-10_1001_가상상점.pdf`. 파일 이름에 사용할 수 없는 문자는 안전한 문자로 바꾸고, 이름이 충돌하면 알리고 중단합니다.
9. 같은 연도·월과 거래처의 기존 PDF는 새 PDF 생성에 성공한 뒤 덮어씁니다. 작업용 파일은 정리하고 생성된 PDF 수와 오류를 알립니다.

## 오류 처리와 주의 사항

- 원본 파일, 필요한 시트나 제목이 없으면 무엇이 없는지 알리고 중단합니다.
- 날짜, 수량, 단가 등 청구에 필요한 값이 없거나 해석할 수 없으면 해당 행을 알리고 중단합니다. 거래처코드가 거래처 시트에 없거나 중복된 경우에도 중단합니다.
- 해당 월의 매출이 없으면 PDF를 만들지 않고 결과를 알립니다.
- PDF 변환 프로그램이 없거나 실행에 실패하면 원인을 알립니다. 새 PDF가 완성되기 전에 기존 PDF를 지우거나 덮어쓰지 않습니다.
- 엑셀 계산식이 실제로 다시 계산되고 PDF에 표시되는지 확인합니다. 특히 16행을 넘는 내역은 모든 금액이 합계에 포함되는지 별도로 검산합니다.
- 양식에는 공급자 정보와 입금 계좌 등 기존 문구가 있습니다. 원본 내용을 그대로 사용하므로 실제로 사용할 수 있는 정보인지 사용자가 확인해야 합니다.

## 추후 실행 방법

파이썬과 필요한 라이브러리, 계산 및 PDF 저장에 사용할 프로그램을 준비한 후 `03-sales` 폴더에서 실행합니다. 예정 명령은 다음과 같습니다.

```powershell
python 청구서_만들기.py             # 기본: 2026년 10월
python 청구서_만들기.py 2026 11     # 2026년 11월
```

실제 프로그램이 아직 없으므로 지금은 실행할 수 없습니다. 필요한 설치가 있다면 프로그램 작성 단계에서 이유를 설명합니다.

## 완료 기준

- [ ] 연도와 월을 생략하면 2026년 10월을, 둘 다 입력하면 해당 월을 사용합니다.
- [ ] 해당 월의 매출만 거래처코드별로 모으고, 거래처마다 PDF 하나를 만듭니다.
- [ ] 청구서에 거래처명·우편번호·주소와 각 내역의 날짜·상품명·수량·단가가 정확하게 표시됩니다.
- [ ] 양식의 금액·부가세·합계가 다시 계산되고, 전체 내역과 합계를 독립적으로 검산한 결과와 일치합니다.
- [ ] 16행 초과 내역도 누락이나 잘림 없이 한 PDF에 들어갑니다.
- [ ] 파일 이름에서 연월과 거래처를 알 수 있고, 같은 달의 같은 거래처 PDF는 새 파일 생성 성공 후 덮어씁니다.
- [ ] 입력 오류와 변환 오류를 이해하기 쉽게 알리고, 두 원본 엑셀 파일은 유지합니다.
